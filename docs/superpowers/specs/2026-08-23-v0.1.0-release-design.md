# v0.1.0 Release Design

## Goal

Publish the first formal GitHub Release for Cantonese Learning Platform. The release will be concise, written in English, and aimed primarily at Cantonese learners rather than developers.

## Readiness Decision

The project is suitable for a `v0.1.0` release because:

- `main` is clean and synchronized with `origin/main` at commit `01e4b2f5938081239d97ab565bf9af6e9c49d69b`.
- The repository is public, uses the MIT License, and includes an English README.
- No Git tags or GitHub Releases currently exist.
- The listening audit passes for 31 days, 3,935 study items, and 2,205 sentence audio files.
- JavaScript syntax checks and Git integrity checks pass.
- A tracked-file scan found no obvious embedded credentials.

`v0.1.0` is appropriate for an initial public version that is usable but does not claim API or product stability.

## Release Identity

- Tag: `v0.1.0`
- Tag type: annotated Git tag
- Tag target: `01e4b2f5938081239d97ab565bf9af6e9c49d69b`
- Tag message: `Cantonese Learning Platform v0.1.0`
- Release title: `Cantonese Learning Platform v0.1.0 – Initial Public Release`
- Release type: full release, not a prerelease or draft

The tag target is fixed to the already validated public-project commit. Release-planning documentation committed afterward will remain outside the `v0.1.0` snapshot.

## Release Notes

```markdown
## Initial Public Release

Welcome to the first public release of Cantonese Learning Platform, a dependency-free web app for structured Cantonese study. It includes 31 days of Hong Kong–focused learning material and runs directly in a web browser.

## Current Features

- 31 days of structured Cantonese lessons
- Cantonese text, Jyutping, and Mandarin explanations
- Quiz modes for pronunciation, meaning, and reverse recall
- Daily listening practice with recorded sentence audio
- Automatic retry scheduling for unfamiliar cards
- Progress saved locally in the browser
- JSON import and export for moving progress between devices
- Responsive and accessible interface
- No build step or package installation required
```

## Publication Flow

1. Reconfirm that the target commit exists locally and on `origin/main`.
2. Re-run the listening audit and JavaScript syntax checks.
3. Reconfirm that neither `v0.1.0` nor a GitHub Release with that tag exists.
4. Create annotated tag `v0.1.0` at the fixed target commit.
5. Push the tag to `origin`.
6. Create the GitHub Release using the exact title and notes above.
7. Verify that the remote tag resolves to the target commit and the Release is public, published, and not marked as a prerelease or draft.

## Failure Handling

- If a local or remote `v0.1.0` tag appears before creation, stop and compare its target instead of overwriting it.
- If validation fails, do not create the tag.
- If the tag is created locally but cannot be pushed, keep the local tag and diagnose the push without moving or force-pushing it.
- If the tag is pushed but Release creation fails, keep the immutable tag and retry only the GitHub Release creation.
- Never force-update the published release tag.
